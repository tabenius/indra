# Indra project instructions

Read `README.md` and `docs/upstream.json` before work. This is a local development
copy of OSHI's published core, not the full shipped application. Never imply an
Indra app, isolation boundary, or security property exists without evidence.

- Keep upstream license and history. `README.upstream.md` preserves the source
  README as imported; `README.md` describes Indra.
- Main-net compatibility is a requirement. Do not globally replace OSHI names,
  UUIDs, protocol strings, signed fields, or public keys for a branding change.
- Read `docs/indra-networks.md` before transport changes. The second network
  is planned, not active. Do not send development traffic into upstream relays.
- Canonical logo artwork is SVG in `web/assets/`. PNGs are generated by
  `tools/render_brand.py`; use the simplified favicon at very small sizes.
- `web/` is a standalone static site. Preserve local fonts/assets, keyboard
  access, clear project status, and narrow-screen layout.
- Run `python3 tools/verify_indra.py` after site or asset changes. Use browser
  proofs after visual changes. Verify native code with target-platform tooling
  before claiming a build; Linux cannot validate Apple framework behavior.
- Optional cross-disciplinary knowledge lives in `~/AGENTS/DOMAINS/MESH/`.
  Load its index and relevant skills, not the entire library.
- Publishing, signing, and deployment facts need actual execution and receipts.
  Do not commit or push unless the user asks.
